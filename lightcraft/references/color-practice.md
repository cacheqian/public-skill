# 调色实践：从画面关系到具体动作

在需要实际改变配色、处理肤色/天空/混合光或迁移参考风格时读本页。先确认 [色彩解释与 LUT 边界](color-and-rendering.md)，控件实时 ID 以 `list_controls` 为准；本页给出条件化方法，不保证任何固定参数跨图有效。

## 1. 全局、色相、明度分区和空间区域怎样选

| 目标 | 优先考虑 | 观察及转向条件 |
|---|---|---|
| 大多数区域有一致且不希望的色偏 | WB temp/tint | 看多个可信参照与主体；若室内外两区反向变化，转混合光局部处理 |
| 整张颜色普遍过浓/过淡 | saturation/vibrance 小幅候选 | 两者的实际响应依实现与图片而异；vibrance 不是自动保护所有肤色的保证。看高彩度区和中性色是否失真 |
| 某一色系的色相、彩度或明度需要改变 | `mixer.<band>.hue/sat/lum` | 同色物体可能一起变化；若只允许改变一处，增加空间隔离。相邻色带与渐变一起检查 |
| 同一明度范围想有统一色彩倾向 | `grading.shadows/midtones/highlights` | 明度分级不识别对象；暖高光也会影响白衣，冷阴影也会影响脸部阴影，须检查主体 |
| 某个物体或光区需要区别对待 | 局部蒙版及局部色彩控件 | 看遮挡和边缘；局部 temp/tint 与全局 Kelvin 并非同一数值标度，不能直接抄值 |

一次先解决一个维度。例如红衣太抢，先试降低其彩度；仍太亮才评估明度。不要同时大幅改 hue/sat/lum，失去辨别有效原因的机会。HSL/Mixer 的 hue 单位不要当角度；grading 的 hue 与 mixer 的 hue 也不能互抄。

## 2. 肤色：保持光照下的可信关系

1. **先看照明**：脸、颈部、耳朵、衣物与背景是否共享主光？暖夕阳、舞台彩光下的肤色不必回到日光外观。不同位置的皮肤受光不同，不能要求全部相同颜色。
2. **先排除全局原因**：脸偏橙而白衣、墙面也偏暖时，先评估 WB 或全局风格；其他区域正常、只有脸异常时，再做局部。脸太暗也可能显得脏，不要只靠去饱和处理明暗问题。
3. **定位颜色范围**：红色、橙色、黄色及其邻近带都可能参与。用小幅试调确认实际影响，不把“肤色=orange”写成固定映射；木墙、落叶或灯光可能同属该色带。
4. **分开处理问题**：泛红可试相应范围的彩度/色相，阴影偏绿可试局部 tint，亮斑可能主要是明暗问题。改变一个因素后看肤色是否灰白、蜡黄或失去血色。
5. **验收**：先全图看人与环境是否协调，再看脸颈交界、唇色、阴影、毛发边缘和皮肤纹理；保留自然差异。没有受控参照时只能评价观感，不声称测得绝对肤色正确。

## 3. 天空、植被与城市灯光

### 天空：颜色与层次分开看

天空过亮先评估明暗；天空过艳才评估 blue/aqua 彩度；想加深天空可试对应明度，但必须检查云边、天际线、渐变和蓝色物体。由浅蓝到紫蓝的断层、天空发黑、云边光圈出现时减弱或改局部。暮色常同时有蓝、灰、紫和地平线暖色，不把整片天空统一染成纯蓝。

### 植被：找出“荧光感”的来源

先排查已有饱和/去雾/强对比。green 与 yellow 可能共同影响叶片；先小幅降低过量彩度，必要时再试 hue/lum。自然目标下看阳光叶、阴影叶和枯叶是否仍有区别；叶片变泥灰或肤色、黄色建筑被连带改变时缩小范围。参考风格要求偏黄绿、青绿时按参考试，不把一种绿当通用正确颜色。

### 城市与霓虹：亮点不等于有纹理的高光

保留不同光源色相及深色支点。先读灯牌和建筑重要亮部是否仍有可辨信息；必要时局部压亮度或相应颜色彩度。灯泡、太阳、反光点允许很亮；把所有灯压灰通常削弱夜景。夜空过蓝或橙灯过浓时优先处理该范围，避免为了一个灯牌让整张失去色彩。源 JPEG 已剪切的灯牌不能靠去饱和或高光滑杆恢复文字。

## 4. 混合光：确定主光，再处理次要光区

1. 标出主体所在主光区与其他光区，先明确想保留多少冷暖差异。产品色准与室内氛围的目标可能不同。
2. 全局 WB 只建立合理基线；若主体自然而窗外变蓝，判断这是否符合场景与意图，不自动全中性化。
3. 在确有不希望色偏的区域做局部 temp/tint 或颜色调整。过渡范围要对应光线的实际渐变，不能沿人物轮廓生硬分割同一片光照。
4. 看跨区皮肤、白墙和阴影过渡。若怎么调都不能同时自然，可能有复杂光谱/反射或源数据问题；降低目标强度并说明限制，不用更多全局色偏互相抵消。

## 5. 把风格描述变成可试的步骤

下面均是候选方法，未作为统一预设实测。先从目标图与参考图选最相关的一两项，不必执行整行。

| 方向 | 先建立的关系 | 可尝试的手段 | 失败信号 |
|---|---|---|---|
| 柔和暖调 | 主体有分离，高光柔和，暖主光仍成立 | 先整理高光/曲线过渡；若仍需染色，仅对适当明度区试弱暖倾向，再管理过强黄橙彩度 | 全图泛黄、肤色橙红、黑位发灰；“柔和”不等于抹纹理 |
| 冷暖分离 | 主体/背景或亮/暗区域有可解释的温差 | 主体 WB 稳定后，对阴影/高光分别试低彩度倾向；主体与背景同明度时用空间蒙版 | 人脸阴影青绿、白衣被染、原本有色灯光失真 |
| 通透风景 | 近远层次、天空渐变、主色清晰 | 先解决明暗；按确实存在的雾气决定 dehaze，再独立整理蓝/绿/黄色带 | 远景被拉成近景、天空断层、植被荧光、山脊亮圈 |
| 柔和淡彩 | 有明度支点，主色低彩度但不脏 | 先整理高光和中间调，再降低相关范围彩度；只有确有需求才温和抬黑 | 去饱和后灰脏、主体消失；继续加颗粒无法修复这个问题 |
| 浓郁暗调 | 暗部仍有必要层次，主色受控 | 保持主体可读，温和整理黑位/曲线和颜色竞争；控制高光彩度 | 大片死黑、强色块、人物灰脏；不要用整体欠亮代替暗调 |
| 黑白 | 主体与背景在明度上仍能分开 | 启用已发现的黑白处理，按原有颜色关系试 `bw.<band>`，然后塑造曲线 | 衣物/皮肤/背景合并、天空斑驳；不只一键去饱和就结束 |

对于分级，先选择色相，再从低彩度试起，比较“有此分级/无此分级”。还没明确颜色作用时不要叠 grain、vignette 和多条通道曲线。具体 hue 数字取决于当前实现与观察，不用色轮名称冒充经过验证的参数。

## 6. 参考图迁移的比较方法

用简短关系记录目标，例如：“参考主体比背景亮；阴影较冷；绿色彩度较低；高光过渡柔和。”先比较结构与明暗，再比较色彩，最后质感。无需同场景也可迁移关系，但参考里的侧光、景深、逆光轮廓或雾气未必能靠调色重建。

每轮只验证最重要的关系，参考与目标保持相近查看尺寸和相同显示解释。若有条件做颜色数值比较，先核对 profile、白点与采样对象；不能用两张不同内容的 RGB 均值相近来证明匹配。用户对冷暖、黑位或浓淡的反馈可以形成偏好，但只在相应任务范围内复用。
