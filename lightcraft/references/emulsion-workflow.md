# Emulsion 风格提炼与自动筛选

用于用户要求胶片方向、风格探索或补充 Skill 案例时。普通自然修图继续走主流程，不默认套预设。保留一个 LightCraft Skill，六类风格按任务读取本页和小型参数库；不用为胶片名字分拆六个 Skill。

## 1. 这批材料是什么

提炼自 EmulsionPresets 固定提交 `0cdb71c60603867a046bc92c63617feec7894dd1` 的六个基础版 XMP，不含 +1/+2 推片版本。原始参数是作者的创意配方，没有实测胶片响应、同场景胶片参考或 Adobe/LightCraft 渲染一致性证据。

[参数库](emulsion-recipes.json) 内每个条目包含来源路径/链接/原文件 SHA256、LightCraft 部分设置、试过的强度及筛选范围。[MIT 许可](emulsion-license.txt) 随改编参数保留。这里打包的是六份重新限定作用范围的参数，不含全部 451 个预设、外部源码、LUT 或用户照片。

三种材料的作用不同：正样本帮助描述目标关系；同一照片的候选前后图帮助识别改善与副作用；参数帮助复现操作。原始照片不天然是负样本，处理后也不天然是正样本。每对样本必须附目标、起始状态、实际改动和保留/减弱/淘汰理由。

## 2. 直接导入 XMP 的实际兼容差异

在 LightCraft 0.13.0 的隔离会话，对六个原始 XMP 及仅修正别名的副本进行了导入、应用和读回：

| XMP 字段 | 此版本 LightCraft 行为 | 本 Skill 的处理 |
|---|---|---|
| `Exposure2012`、对比、HSL 等多数控件 | 能转换，但跨引擎同值不保证同效果 | 选取有用的风格关系；保留当前曝光、高光、阴影和白场修正 |
| `ColorGradeHighlightHue/Sat` | 出现在 `unmapped`；原预设的高光着色未迁移 | 直接生成 `grading.highlights.hue/sat` |
| `ColorGradeShadowHue/Sat` | 同样未映射 | 直接生成 `grading.shadows.hue/sat` |
| `ColorGradeBalance` | 未映射；LC 此时认 `SplitToningBalance` | 生成 `grading.balance` |
| `GrainRoughness` | 未映射；LC 认 `GrainFrequency` | 本批不动颗粒；保留原值供后续单独试验 |
| `Treatment` | 字段未映射；HP5 的 `ConvertToGrayscale=True` 实际转换为黑白 | 使用明确的 `treatment: bw` 和 `bw_mix` |
| `Look: Adobe Color/Vivid/Monochrome` | 导入报告将基础名字映射到 `lc.color/lc.vivid/lc.mono` | 这不是 Adobe 渲染一致性；参数辅助脚本保持当前 profile |
| 0…255 点曲线 | 导入会归一到 0…1；仍不能保证跨引擎一致 | Cine/Velvia 仅迁移非恒等 master；不叠加原文件重复的 RGB 曲线 |

修正别名的测试副本中，原本丢失的高光/阴影色调、balance 等能够读回。没有修改用户软件或上游仓库。以后版本须核对 `preset.import` 的 `unmapped` 和应用结果，不能把这份快照当永久不支持列表。`RequiresRenditionBehavior` 等标记与实际漏掉颜色参数分别判断。

若使用原生 `preset.import`，先发现实时命令 schema，再传 `paths`；通过命令工具调用时此版本是 `command_run {id:"preset.import",params:{paths:[...]}}`。确认来源和影响范围后再应用到明确照片 ID。导入成功不等于效果完整，也不代表源预设包含的曝光、锐化、降噪和曲线适合当前图。

## 3. 六个可解释的风格起点

下表描述试调目标，不表示这些相机/胶片的实测复刻。当前筛选结果和适用范围看 [实测与取舍](#6-已执行的首批实测与取舍)，参数库条目的 `evaluation` 字段记录逐图决定。

| ID / 来源基础版 | 提炼的关系 | 优先观察 | 失败时怎样改 |
|---|---|---|---|
| `portra-soft` / Kodak Portra 400 | 降低少量反差，适度抬黑；橙色略提明，绿/蓝节制；弱暖高光 | 皮肤是否可信、黑色物体是否仍有体积 | 发灰就减弱黑位/反差部分；橙色控件同时影响衣服和背景，必要时缩小区域 |
| `gold-warm` / Kodak Gold 200 | 黄橙主色与暖高光，部分绿/蓝收敛，阴影保留冷色 | 白杯/白衣、肤色、黄橙物体是否过艳 | 不靠全局 WB 再染黄；先减橙黄彩度或高光着色，保留原光源 |
| `chrome-muted` / Fujifilm Classic Chrome | 多个色系降彩度，反差与较深黑位建立纪实层次 | 肤色/暗主体是否被一起压暗 | 中央目标变闷就减弱对应 HSL 明度/黑位，而非额外全局曝光补偿 |
| `cine-cool-warm` / Cinestill 800T | 弱冷阴影与暖高光、柔化局部反差、有限抬黑/压白 | 夜景黑位、灯牌颜色、皮肤或灰墙是否被染色 | 暗部发灰先减弱 master 曲线及去雾负值；不承诺真实卤化物光晕或 halation |
| `velvia-vivid` / Fuji Velvia 50 | 更强反差和非线性色系浓度，蓝/绿加深 | 饱和物体、天空渐变、皮肤、暗部层次 | 先减强度/目标色系彩度；不作为人像自然修图默认方向 |
| `hp5-mono` / Ilford HP5 Plus | 明确转黑白，橙红提明、蓝压暗，有限反差和黑位 | 脸/衣物/背景明度区分、蓝天是否压死 | 单独调整黑白混色；增加颗粒需另看交付尺寸与真实噪声 |

源文件中所有方向都带颗粒和 `Sharpness=10`，部分还写降噪 0。它们不是跨图质量准则。本批**保留现有 detail、grain、profile、WB、局部处理、裁剪和几何**，也保留 light.exposure/highlights/shadows/whites。源文件的曝光 +0.5/+0.75 等没有被当作胶片风格移植。

HP5 原文件还包含冷暖着色，本批中性黑白方向不迁移这组颜色。已有的人工调色仍被保留；若它令黑白产生色调，应实际看图，再按目标决定是否改动，而不是悄悄清空。Cine/Velvia 的 RGB 重复曲线没有照搬，所以这里也不是六个源 XMP 的等价转换器。

## 4. 从当前基线生成有限范围的参数

辅助脚本 [prepare_style.py](../scripts/prepare_style.py) 只读取 JSON，输出供 `set_develop.settings` 使用的局部 patch；不会连接应用、写照片、切换选择或导入预设。它依赖 Python 3 标准库。

在 Skill 安装目录内执行，`--baseline` 指向已保存的、未包装的 `get_develop` JSON：

```bash
python3 scripts/prepare_style.py \
  --baseline /absolute/path/before.json \
  --recipe portra-soft --strength 0.35 > /absolute/path/patch.json
```

读取输出内容，再将这个 JSON 对象传给目标照片的 `set_develop {id,settings:...}`。先明确单选目标、检查 Auto Sync，读回并看预览。脚本不决定本次风格是否合适，也不会代替恢复现场工作。

- `strength` 是**从保存基线向该风格目标插值**的 0…1 系数。0 输出空 patch；0.35/0.65 是本批试过的两档，不是摄影定律。此系数不等于原生 `preset.apply` 的 `amount` 语义，不要混用。
- 色相是角度。已有饱和度为 0 时直接取目标 hue、渐增 saturation；非零时按最短圆弧插值。不要把 210° 乘以 0.35 变成另一种颜色。
- HP5 的黑白转换是离散开关，任何正强度都会完全转为黑白；强度只控制所列连续参数。已有黑白图用彩色配方会报错，让代理先判断用户意图。
- 曲线采用 0…1 点列。已有非恒等点曲线或参数曲线时脚本拒绝迁移 master，避免覆盖人工意图。实际检查后可用 `--skip-curve` 保留当前曲线，另试其余颜色关系；这条分支未包含在本批 48 张视觉比较中，须重新看结果。
- 未出现在 patch 中的字段保持不动。白平衡/曝光/高光等保护的是参数值，创意颜色和曲线仍会改变它们对应区域的观感，所以必须看图。
- 每个候选从**同一保存基线**产生。在应用下一候选前精确恢复上一候选碰过的字段，否则不同配方未提及的字段会残留。不要不断把上一轮结果重新当基线，累积染色。用户库只恢复本轮字段；隔离库才能为测试整份还原。
- 恢复时取基线的对应字段值，包括完整旧数组；查明有没有用户插入编辑。脚本既不打印撤销步数，也不保证后台状态未变化。读回发现范围外变更时停止并核对 Auto Sync/目标 ID。

## 5. 用户不逐张评价时的自动流程

用户已要求省略逐张主观评价时，继续独立完成候选、筛选与导出，不把“请选 A/B”当固定关卡。缺乏目标方向时自然修图仍是默认；自动化授权不意味着每张照片都要加胶片效果。

1. 保存输入格式/相机、现有技术与创意编辑、用户目标和同条件预览。选择最符合目标的少量风格；两档强度只在有比较价值时生成，不遍历全部库。
2. 先查命令失败、实际写入、字段覆盖、源图是否完整、导出规格。某项失败，候选尚不能进入效果评选；修正后重试相关部分。
3. 实际看基线与候选的目标变化，再看主体可读性、皮肤/中性色、重要高光、黑位、色彩边缘与质感。允许保留基线。目标没有改善或代价更大时，减弱/局部化/淘汰。
4. 剪切比例、亮度等只产生“需检查此区域”的线索。比如自然修图的新增皮肤剪切应关注；夜景已有点光源剪切并不自动失败；少量彩色霓虹也不因任何通道触顶就全部淘汰。没有对齐、明确参考/色彩空间时不用 DeltaE、相似度或一个美学分数替代判断。
5. 可委派独立模型复核图片和任务，先不提供主审偏好的候选。它必须真实看图；看图能力缺失就记未复核。意见冲突时根据具体区域重新看，不以投票当客观真值。
6. 对照另一张同组或边界照片。单张效果通过只记录这张/这个条件；RAW/JPEG、光线、肤色和现有编辑差异都影响迁移。遇到新条件先降回候选，不能沿用通过标签。
7. 将保留结果重新导出并解码，核对实际尺寸/ICC及查看成品。源图小于目标边长时，这次实测的 JPEG 导出保持原尺寸；本批预览可上采样，不能据此声称新增了细节。
8. 记录“自动筛选通过 / 候选 / 淘汰”与原因、作用范围和证据。**自动筛选通过不等于用户偏好，不等于精确胶片还原。** 用户之后给反馈时补充“这个场景/这个目标”的偏好依据，不将一张图的暖色意见推广到所有照片。

只在任务范围、缺失的必需参考或交付约束确实无法确定时提问；常规风格取舍由代理完成。保存原图、权限边界及外部发布授权继续按主流程处理。

## 6. 已执行的首批实测与取舍

2026-10-25，Windows LightCraft CLI 0.13.0 的独立 `--demo --compact` 内存会话，使用 `import mode:add` 引入四张真实照片。没有连接桌面用户库做试调。

| 样本 | 输入与基线 | 能检验什么 | 不能推广到什么 |
|---|---|---|---|
| 室内人像 | NASA Eileen Collins 公有领域 PNG，512×512，已显影图 | 单个肤色/橙色衣服、黑色头盔及白背景的关系 | 多种肤色、真人修肤、高 ISO/100%细节或人像 RAW |
| 咖啡静物 | Rachel Michetti CC0 PNG，600×400，暖色成片 | 饱和红橙、白杯、木纹、金属反光 | 商品标准色测量或中性原始光线 |
| 蓝调户外发射场 | SpaceX 公有领域 JPEG，640×427 | 蓝天层次、暗钢结构、暖点光源 | 日光绿色植被、逆光风景、天空渐变高位深输出 |
| 霓虹街景 | 相机 RAW；隔离基线曝光 +0.2、高光 −45、阴影 +18，As Shot WB | 这张 RAW 上的红蓝灯牌、黑位、行人及混合光关系 | 所有相机 RAW、所有夜景，或用户已选择了某种风格 |

每张六种配方 × 0.35/0.65，共 **48 个实际渲染候选**，与各自起始图同尺寸同裁剪比较。前三张输入已显影且分辨率小，1200px 预览有上采样，判断限于整体色调和可见主体关系，不冒称 100%纹理评价。另有六个配方各一个原生 sRGB JPEG 导出经过解码、尺寸和非空 ICC 检查；导出设置正确不等于六个都审美通过。

已确认的技术结果：六个配方都可执行、读回；现有曝光/WB/profile/crop/detail/grain 等保持；另在含非空旧蒙版与裁剪的隔离图验证作用范围及其他照片不变；原 RAW 的前后 SHA256 一致。原始/别名修正 XMP 的导入差异有单独读回记录。

首批人工目视后的自动筛选记录为 **17 个通过、26 个候选、5 个当前目标/强度下淘汰**。这不是模型准确率；它只是本批有限材料的取舍记录。

| 方向 | 自动通过的低档样本（0.35） | 默认使用范围 |
|---|---|---|
| 柔和 Portra | 人像、咖啡 | 弱柔和目标；其他场景保留候选 |
| 暖调 Gold | 人像、咖啡、霓虹 | 明确暖调目标；高档暖色需谨慎 |
| 纪实 Chrome | 本批四图 | 明确低彩度目标；不冒称自然人像改善 |
| 冷暖 Cine | 蓝调发射场、霓虹 | 弱冷暖/柔化；65% 夜景泛灰淘汰 |
| 鲜艳 Velvia | 无 | 保留为候选；尚缺日光植被和更合适素材 |
| 黑白 HP5 | 本批四图 | 用户要黑白时；人像/咖啡的0.65也可用，默认仍较弱档 |

独立 Claude 未能看图，没有用其技术分析给这些视觉决定背书。范围内新照片仍要逐张看实际结果，不能把这张表当自动无条件应用名单。

**本轮可复用的反例**：

- 咖啡图 `velvia-vivid=0.65` 的任意通道近白像素比例（8-bit 预览中任一通道 ≥254）从约 0.277% 升至 1.839%，约增加 1.562 个百分点。实际看图可见红橙盘面更浓，亮部层次变硬。这个比例是检查通道剪切的线索，不单独证明色域裁剪或 RAW 信息损失。它是“已有饱和暖色主体仍强加鲜艳方向”的减弱信号，不是“所有触顶都坏”的规则。
- `cine-cool-warm=0.65` 在霓虹 RAW 中抬亮了黑位并柔化局部反差，楼体暗部明显泛灰。冷暖关系可见，但自然夜景目标下应降低曲线/柔化强度；想要褪色氛围时该变化可以是有意效果。
- 人像上的 `velvia-vivid` 不适合作为“自然肤色”的默认入口；衣服和肤色共享橙色范围，增加橙色浓度会同时影响二者。要保衣服浓度而肤色自然，应先缩小调整范围，再重新验证。

本批没有胶片实拍目标图，没有去卤化物/真实光晕模型验证，没有全画幅 100% 噪声锐化检查，也没有用户对这 48 个候选的偏好评分。后续增加日光风景、多肤色、混合光组照或不同相机时，按上述协议补证据。
