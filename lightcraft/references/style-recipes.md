# 风格、参考图与批量处理

这里提供可观察的风格关系与执行流程，不提供跨图通用参数。参考图、用户反馈和实际预览决定调整方向；LightCraft 的控件和覆盖语义见 [操作说明](lightcraft-operations.md)。

## 1. 把风格描述拆成能比较的关系

| 维度 | 观察参考图 | 迁移到目标图时的边界 |
|---|---|---|
| 明暗 | 主体明度、黑位、反差、高光过渡、暗部信息 | 不复制平均亮度；不同场景/光比需单独曝光和局部处理 |
| 冷暖 | 高光/中间调/阴影各自倾向、主光色 | 区分灯光与调色；晨昏暖光、霓虹并非可任意替换的色偏 |
| 配色 | 主色、辅助色、被压低的色相，肤色与背景关系 | 保留主体固有色；特定色相控件可能同时改到背景 |
| 质感 | 局部反差、柔和程度、颗粒、锐化 | 景深、失焦、镜头耀斑和实际光线无法保证靠控件复制 |
| 构图/内容 | 比例、主体占比、空间与光影布局 | 只有任务包含构图时才裁剪；色调迁移不等于场景重建 |

“电影感”“胶片感”没有唯一技术定义。先从现有图/参考图推断具体维度；明确名字而没有参考时，可提出合理方向并标注为近似；用户授权自动筛选时自主完成取舍，只有必需信息无法推断时再问。想要精确胶片响应、品牌色或相机模拟时，需相应标准/参照，不能只凭胶片名称承诺。

## 2. 参考图流程

1. 实际看目标图、参考图及当前编辑。缺参考但用户要求按它复制时，先获取参考或说明目前只能按文字方向工作。
2. 选择最重要的两三项视觉关系，并说明哪些差异来自拍摄/场景，哪些可能通过处理接近。
3. 保留目标图已有合理基线，修正影响目标的曝光/WB，再测试风格。技术修正和创意变换分清，但不强行把有意暖光校成全中性。
4. 对较大风格探索保留可恢复状态或明确副本；先用已确认控件做可解释的弱强度候选，再看主体、肤色和关键区域。
5. 适合时使用 LightCraft 已有预设/profile，先查真实 ID 和覆盖范围；不要把 darktable 风格文件、Log LUT 或 OCIO 配置当成原生预设。
6. 同输出条件对照，接受必要的逐图修正。展示效果、解释代价，停止在满足目标的程度，不追求所有颜色像素分布完全一致。

## 3. 可尝试的方向

下表是一般方向。需要带出处的具体参数和已经渲染比较的六类 Emulsion 候选时，读 [风格提炼与自动筛选](emulsion-workflow.md)，其中区分自动通过范围、候选和副作用。

具体的肤色/天空/植被/混合光处理和六种风格的候选动作、失败信号见 [调色实践](color-practice.md)。本页侧重参考图拆解与整组编排；不要把下表当现成预设。

| 目标方向 | 候选关系 | 重点复核 |
|---|---|---|
| 自然暖调 | 保留暖主光，适度管理彩度与高光，暗部不全部染黄 | 皮肤/中性色是否可信，暖光层次是否保留 |
| 柔和/低反差 | 柔化明暗过渡，控制局部反差，按图判断是否抬黑 | 画面是否发灰、主体是否失去分离、天空是否断层 |
| 冷暖分离 | 主体/高光与阴影建立有节制的色彩区别 | 不机械青橙，不把皮肤、白衣或灰墙染成异色 |
| 浓郁风景 | 在合理曝光和色域内突出主色与层次 | 植被不荧光、天空有渐变，去雾不产生亮圈 |
| 黑白 | 先看色彩对象转换后的明度关系，再做黑白混色和曲线 | 肤色、天空、衣物/背景是否失去区分；颗粒不掩盖纹理 |

没有足够光线或源数据时，风格只能做视觉近似。不要用锐化、颗粒或强曲线掩盖源图问题。

## 4. 批量统一：保持关系，而不是参数全部一样

先为整组写一两句共同目标，例如“肤色自然，反差柔和，背景颜色不过分抢眼”；然后分别建立日光、暖灯和蓝调的实现。日光海边与酒店暖灯可以共享彩度节制、主体层次和质感方向，同时保留不同时间/空间的照明特征。

| 要统一的关系 | 比较对象 | 通常需要逐图/分组保留的差异 |
|---|---|---|
| 主体可读性 | 主体相对背景，而非全图平均亮度 | 不同光比、背光面、局部遮挡，曝光及蒙版可能不同 |
| 冷暖与肤色可信度 | 各自主光下的皮肤/中性色 | 日光、钨灯、蓝调现场差异，不设相同 K 值 |
| 配色节奏 | 主色/辅助色与抢眼颜色的地位 | 场景里颜色物体不同，不能按整图颜色均值强匹配 |
| 反差与黑位 | 暗部层次、高光过渡、主体分离 | 夜景允许更深暗部，高调图不必压出同样黑位 |
| 质感 | 同交付尺寸下的细节、颗粒、噪声 | ISO、分辨率、手机 JPEG 已有处理不同 |

已有编辑要保留时，读取每张相关字段，先判断哪些意图应保留。复制一个 group 会替换其相应设置，不能因只勾选“colorGrading”就认定不会覆盖人工调色。需要个别修正时逐图计算；只有确认每张都需要相同增量，才考虑已发现的 `develop.quickAdjust {control,delta,ids}`，它也不保证相同观感。不要用整图 reset 获得“统一起点”。

1. **确定范围**：列出目标 ID/文件/选择，分页拿全；记录每张的已有编辑。没有明确选片/删除任务时，不替用户丢弃照片。
2. **分组**：按同一场景/光源、相机或文件类型、曝光与已有风格分组。室内暖灯和室外蓝调通常先分开建基线；是否共享 WB 目标取决于交付意图与实际画面，不把同一数值当作一致性的保证。
3. **选代表与边界图**：每组看普通图及亮/暗、有肤色、强饱和等容易出问题的图。它们用于验证可共用部分，不把一张成功当整批通过。
4. **分清共用与个别**：风格方向、部分曲线/色彩/profile 可考虑共用；曝光、WB、裁剪、几何、蒙版位置和噪声处理通常要逐图判断。不同 RAW/JPEG 的 WB 标度尤其不能直接复制。
5. **先小范围试**：保存试点图的原值，执行候选，逐张看预览；有异常先分组或降低共用范围，再推广。不同曝光照片可共享视觉方向而使用不同数字。
6. **明确同步字段**：如果用 `develop.copy/paste/sync`，先读实时命令说明，明确要复制哪些组；默认组及准确 group 名称见 [操作说明](lightcraft-operations.md#批量同步的字段与-auto-sync)。不要默认复制整份 settings，尤其不要搬运 masks、crop、WB 和已有人工编辑。
7. **核对执行范围**：多步失败不自动回滚；记录成功/失败 ID，查询实际状态。不要只看第一张或总成功标志。
8. **验证整批**：按组抽查与复核所有异常图；输出每文件结果，核对返回数量/失败项。未逐张看图就说明抽查范围，不能宣称所有照片的视觉质量均已检查。
9. **导出**：使用独立目录和明确冲突策略，逐文件核对实际产物；保留原片和原有编辑的恢复依据。重复执行 unique 导出会产生新文件，不是幂等覆盖。

## 5. 三个外部项目怎样使用

- **darktable**：借鉴场景曝光、明暗映射、色彩和局部处理的分工；模块的参数、算法、顺序和 LightCraft 不同。不要把 filmic/sigmoid/color balance RGB 的数字直接映射成 LightCraft 曲线/分级。
- **Raw-Alchemy**：借鉴“RAW 解码到已知工作空间，转换到 LUT 期望的 log/色域，再做创意处理”的输入契约意识。README 的效果保证不是本 Skill 的验证结果；处理链无法仅靠换一个 profile 名字复现。
- **t3mujinpack**：它为 darktable 制作胶片风格，使用 Lab 曲线及黑白通道混合，并明确风格前后仍需基础处理和微调。借鉴有限模块、先有合适基线再加风格的做法；保留用户有意的色光，不照搬其较中性的基线建议成所有照片规则。没有转换/实测时不承诺导入 `.dtstyle`，也不承诺“精确 Portra/Velvia”。

本 Skill 没有打包上述项目的源码、LUT 或原生预设，也不自动下载这些项目。另有六种 Emulsion 来源的局部参数与 MIT 许可，见 [风格提炼](emulsion-workflow.md)。来源版本与具体证据见 [来源与边界](sources.md)；流程实际验证情况见 [验证记录](validation.md)。
