# 从照片现象到调整假设

这是摄影与调色的工作流综合，不是 LightCraft 自动诊断算法。先看用户目标，再通过预览验证。调用方法见 [LightCraft 操作](lightcraft-operations.md)，色彩解释见 [色彩与渲染](color-and-rendering.md)。需要把候选落实到控件时，读 [明暗与控件选择](tone-and-tools.md)、[调色实践](color-practice.md) 或 [局部处理](local-editing.md)。已执行的有限实片过程见 [案例](cases.md)。

## 先回答五件事

1. **希望观众看什么？** 识别主体、视觉重心和叙事；亮处不一定是主体，暗部也可能有意保留。
2. **希望保留什么？** 晨昏暖光、蓝调夜景、舞台有色光、高调/低调、已有人工编辑，都不是默认需要消除的问题。
3. **问题覆盖多大范围？** 全局曝光/白平衡、某一光源区域、特定色相、主体局部、几何构图、噪声细节分别处理。
4. **手头证据能说明什么？** RAW/JPEG、预览回退、当前编辑、参考图、显示/输出条件。没有直方图就不声称测到剪切；只有缩略图就不声称检查过原尺寸毛孔/噪声。
5. **什么变化算改善？** 用可观察的关系描述，例如“人物更可读、背景层次保留”，而非“整体曝光必须提高多少”。

## 调整前的候选原因与鉴别

| 现象 | 候选原因与进一步观察 | 候选动作 | 副作用与保留/回退条件 |
|---|---|---|---|
| 整体暗、主体也难辨 | 夜景意图？已有曲线压暗？高光还有余量？ | 小幅曝光或中间调关系；必要时局部提亮 | 主体改善但重要高光消失，就缩小或改局部；夜景变白天则回退 |
| 人物暗、背景正常 | 逆光/侧光，还是全图基线偏暗？看脸部而非整图平均 | 局部蒙版提亮，必要时温和全局配合 | 检查发丝/轮廓光晕、肤色、脸部噪声；不要把背景全部压灰 |
| 高光白块 | 当前输出顶白、源数据剪切、反光点？查看是否为应保留细节 | 尝试降低曝光/高光；必要时局部 | 若源信息缺失就说明；不要以恢复灰块冒充恢复纹理，也不要求灯泡/太阳有纹理 |
| 暗部发灰、层次弱 | 有意雾感？预设抬黑？提阴影过量？ | 调整黑位/对比/曲线，或缩小先前提暗部幅度 | 不压掉关键暗部；雾景的空气感应保留，不一律去雾 |
| 整体黄/蓝/绿/洋红 | 光源本色、WB、输入解释还是创意风格？比较可信中性参照 | 主光源 WB 或局部修色 | 参照改善但人物/其他光区变差，就分区处理；禁止统一色温目标 |
| 人像橙红、皮肤不自然 | WB、全局饱和、局部色相、色彩映射都可能相关 | 修正相关因素；必要时局部 mixer/分级/蒙版 | 皮肤变灰、失去血色或背景同色物体被误伤时回退；不设肤色 RGB 常数 |
| 绿叶荧光、天空过艳 | 全局饱和、HSL、去雾或 LUT？是否存在通道/色域问题？ | 针对色相/区域温和修正，检查输出条件 | 叶片不要泥灰，天空保留渐变；不要靠全图去饱和掩盖局部问题 |
| 边缘有亮圈、局部发脏 | 清晰度/去雾/锐化太强，或蒙版边缘过硬？ | 降对应效果，改善蒙版过渡/作用区域 | 对比全图与局部；不能以缩图看不见光晕为通过 |
| 高 ISO 图噪声明显 | 提暗部、锐化、欠曝、压缩或纹理本身？ | 先稳定曝光，再平衡降噪/锐化；已装模型且格式支持时才考虑 AI | 检查毛发、文字、纹理是否被抹；后期提亮不等于提高拍摄信噪比 |
| 图软/细节少 | 失焦、运动、景深、低分辨率还是解码/预览？ | 能处理的局部对比/锐化，或换更完整输入 | 不承诺还原失焦细节；不足分辨率时停止细节结论 |
| 建筑歪/主体位置弱 | 透视、水平、摄影意图？预期比例是否允许裁边？ | 几何、水平、裁剪分开试 | 检查主体比例、裁切边界与 Constrain Crop；不无条件拉直所有倾斜构图 |

每行都是候选推理，不能把“看起来偏暗”直接升级为“拍摄欠曝”。同一现象可能需要不同路径。

## 一次自然修图怎样推进

1. 记录本轮基线及已有编辑，确认用户要保留的部分。
2. 若输入解释或白平衡明显影响全图，优先处理；若已有基线合理，直接修局部问题。构图改动按用户目标决定，不强制先裁剪。
3. 先做最影响主体/氛围的一项假设，必要时联动少数相关控件。每一轮都读回、渲染和对照。
4. 明暗关系稳定后检查色彩，再评估局部质感与输出细节；发现相互影响时允许返回前一步。
5. 达到目标就停止；缺少足够画面证据时承认未知。连续调整方向摇摆，应恢复最佳版本并说明取舍，而不是积累更多滑杆。

自动调整和预设都是有副作用的候选工具：读取其覆盖范围，适合时才用。用户已做了人工编辑时尤其不能先“全自动”再试图找回原风格。

## 针对题材的观察重点

| 题材 | 优先保持 | 额外检查 |
|---|---|---|
| 自然人像 | 主体可读性、现场光、肤色之间的关系 | 肤色与颈部/背景协调，纹理、面部噪声、发丝蒙版 |
| 风景/晨昏 | 时间感、空气透视、前中后景关系 | 天空渐变、重要高光、植被彩度、去雾光晕 |
| 夜景/舞台 | 暗调与光源色彩 | 霓虹色相、暗部色块、局部过亮；不要求全图中性 |
| 产品/中性色交付 | 用户提供的颜色参照与输出规范 | 无受控参照时只能改善观感，不能保证品牌色/商品色准确 |
| 建筑/室内 | 几何关系、主光与窗外光的协调 | 广角变形、裁边、混合光；窗外与室内未必能同时完全中性 |

## 如何看一轮是否值得保留

同尺寸 A/B 先看整体目标，再检查与修改相关的局部。应能具体说出“改善了什么、代价是什么”；说不出来时不要仅凭数值变化宣称成功。

- 目标改善、无明显新问题：保留并继续下一个必要问题。
- 目标改善但质感/高光/肤色受损：降低幅度或换局部策略。
- 新问题大于收益、与目标无关：恢复本轮字段，保留用户原状态。
- 目标本身是取舍：展示候选版本并请用户决定；不要用更多参数替用户决定审美。

## 待验证的摄影案例

逆光人像、黄金时刻、蓝调夜景、混合光人像、绿叶天空、高 ISO 六类可用于建立案例集。每个案例至少保留：使用授权、源文件类型、目标、初始编辑、基线图、候选设置、前后图、局部检查和最终决定。没有这些证据时，仅称为案例设计或经验假设。

这些决策借鉴 darktable 对场景明暗/色彩/细节的模块划分，并结合 Colour/OCIO 的颜色解释边界；它们不是 darktable 算法或参数的逐项移植。具体来源见 [来源与边界](sources.md)。
